# Bennett Usage UI/UX 重构设计 Spec

## 1. 项目本质

Bennett Usage 是一款常驻 macOS 菜单栏的本地 AI coding agent 用量监控工具。它不是面向管理层的 BI 仪表盘，也不是需要教会用户的新产品；它的核心价值是让开发者在不离开当前工作上下文的情况下，快速确认今天消耗了多少 Token、花了多少钱、主要由哪些 Agent 和模型造成，以及数据是否新鲜可信。因此，重构的核心不是增加功能，而是把复杂数据压缩成清晰的判断顺序：先看结论，再看原因，最后才进入探索。三个界面必须形成同一套叙事语言：菜单栏负责速览与行动，Dashboard 负责解释与比较，Settings 负责配置与维护。

## 2. 目标受众与使用场景

核心用户是同时使用多个 AI coding agent 的开发者、软件团队负责人和独立开发者。典型场景包括：早晨第一次打开菜单栏确认昨日消耗；编码过程中发现费用或 Token 异常上升；项目结束前比较 Agent、模型与项目分布；发现数据没有更新时判断是否需要重扫；更新价格、汇率、语言、主题或检查版本。用户通常处于高专注工作状态，不愿阅读教程，也不想离开终端或编辑器太久。任何要求额外学习、层级过深或状态不明确的方案都会增加认知成本。

## 3. 核心信息与内容优先级

全局第一优先级是“今日/当前范围的 Token 总量与预估费用”；第二优先级是“数据新鲜度、同步状态与异常”；第三优先级是“最高贡献 Agent、模型或项目”；第四优先级才是完整趋势、分布、热力图与明细。全局控制只保留时间范围、Agent 筛选、刷新/同步和设置。Dashboard 首屏需要在不滚动的情况下建立结论句、数据证据和探索入口，但不能让所有模块同时使用强边框、强色彩或大数字。菜单栏弹窗不复制完整 Dashboard，只提供三秒速览和四个明确动作：打开 Dashboard、立即同步、设置、退出。Settings 保持五个稳定分类，但必须让当前 Agent 连接数、数据库状态、更新状态和隐私承诺持续可见。

## 4. 情感基调与设计原则

气质应当是“精确、安静、可信”，接近高级系统工具与科学仪器的结合，而不是消费级健身应用或霓虹科技大屏。视觉设计允许三个方向有显著差异，但都必须遵守：数字优先、颜色有语义、状态有层级、控件可预测、平台习惯可预期、失败状态可恢复。拒绝通用紫色渐变、无意义 Bento 卡片墙、每个标题配图标、所有数字都做成英雄、装饰性 3D、虚构指标、用颜色代替状态文字。过犹不及的留白同样不可接受：安静不等于空，半屏空白必须由构图、节奏或明确的内容缺失状态承担。

## 5. 输出格式与三方向要求

本次先产出三套单文件 HTML 真实视觉稿，统一画布为 1920 × 1500。每套都必须同时展示 Dashboard（目标 1080 × 720）、菜单栏弹窗（360 pt 宽）、Settings（750 × 510）和一份简短设计签名说明。三套方向使用同一份真实内容与相同数据规模，布局骨架必须不同，不能只是换色。

- 方向 A：秒数轮盘抽中网页风格库第 19 号 Swiss Monochrome。采用近白底、黑色高对比、细规则线、极少圆角、结论式大数字与精密栅格，重点是把当前界面从“卡片墙”改成“数据简报”。
- 方向 B：现实参照采用 Apple Health 的信息组织方式——先给整体状态，再给 highlights 与趋势，交互图表承担深入探索；视觉上使用柔和浅色、连续容器和明确语义色，但保留 macOS 工具感，不做拟物或消费级夸张。
- 方向 C：顶级定制锚点采用 IBM Carbon 设计团队的企业数据产品方法。使用石墨色、模块化网格、清晰分区标题、状态条与等宽数字，强调可访问性、可扫描性与高数据密度，适合重度分析但仍保持菜单栏入口的轻量。

## 6. 视觉母题推导

这个产品独有的视觉母题不是“AI 星光”或抽象 Token 粒子，而是**能量流与账本刻度**：Agent 消耗 Token，如同一组工作流在不同时间汇聚成可读的能量；本地数据库与同步状态则像稳定的测量刻度，提供可信参照。三个方向分别用规则线刻度（Swiss）、柔和进度环与趋势（Apple Health）、状态矩阵与模块刻度（Carbon）表达这一母题。form 来自内容的具体地方是：所有方案都让“时间范围、当前结论、贡献来源、同步新鲜度”成为结构骨架，而不是套用通用 Dashboard 模板。

## 7. 已知约束

- 不更改数据模型、解析器、数据库、同步、计价、汇率和隐私行为。
- 保留中英文、本地化、浅色/深色/跟随系统、键盘快捷键与独立窗口行为。
- 实现阶段优先使用 SwiftUI 原生控件和语义样式，减少自绘控件的辅助功能成本。
- 原型中的数值沿用现有截图；不把视觉稿当作生产数据或性能基准。
- 现有 Agent 色彩映射应保持稳定，但可在正式实现中将“分类色”和“交互色”解耦。

## 8. 验收标准

三套方向必须做到：首屏主结论无需解释即可理解；时间范围和 Agent 筛选位置稳定；状态、颜色和文本语义一致；菜单栏弹窗不超过三层信息；Settings 没有大面积无意义空白；正文、标签和控件满足可读尺寸；三套截图无裁切、无溢出、无低对比文字；用户能从截图直接比较布局逻辑，而不是只比较颜色。
